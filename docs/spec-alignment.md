# Aruna Spec Alignment

## Current status

Aruna is aligned with the compiler-first direction of the RFC, and the core MVP contract — serialization boundary, fixed-window rate limits, the contract snapshot, contract diff, and package-consumption validation — is now implemented and aligned. Two primitives have since been added on top of the action surface — the `defineSignal` server→client push channel and a schema-driven binary codec with numeric width hints (see [Added beyond Phase 1 action transport](#added-beyond-phase-1-action-transport)). Signals are compiler-discovered (recorded in `manifest.signals`, listed by `aruna inspect signals`, and included in the contract snapshot). The remaining compiler-side work is stabilization and a create-app starter contract, not a policy/capability system.

`apps/rbxts-harness` now intentionally mirrors Recommended Layout v0 closely enough to serve as the realistic starter/reference harness, while still remaining harness metadata rather than generated Rojo output or create-app scaffolding.

Phase 1 verification is green: `cargo test`, `pnpm typecheck`, and the spec smoke commands (`aruna check`, `aruna inspect modules`, `aruna inspect graph`) all pass, and the unit/contract suites are green. The Rust compiler parser is now OXC; the RFC's "SWC-based" references are superseded by the completed Phase 1.1 OXC migration. Generated action stubs are emitted as compact, deterministic single-line type aliases.

Public package subpaths for packed installs are complete: root re-export shims build to `packages/aruna/*.js`/`*.d.ts` via `tsconfig.shims.json`, ship through `files`, and back the subpath `exports`, so `packages/aruna/test/public-subpaths.test.ts` passes.

Package consumption uses a vendored-runtime model. A roblox-ts-native runtime lives at `packages/aruna/roblox/` (separate from the Node reference runtime under `packages/aruna/src`, which vitest validates). `aruna build --emit-runtime` vendors it into the consumer's `<generatedDir>/runtime/` as project source, and `aruna doctor --fix --emit-runtime` installs the `aruna/*` → vendored-runtime tsconfig `paths` aliases. With `default.project.json` mapping the full `out` tree, `rbxtsc` compiles the whole consumer project — including the vendored runtime — to Luau. Both `apps/package-consumption-harness` and the packed `pnpm verify:package-consumption` tarball smoke compile to Luau end-to-end; `pnpm test` and `pnpm typecheck` are fully green. The native runtime is intentionally thin (schema string/number/boolean/object/array/optional/literal/enum/union, `defineAction`, client `invokeAction`, server dispatch, a default `RemoteEvent` action transport, `plain-data-v1` serialization plus fixed-window rate-limit enforcement in dispatch, the `defineSignal` server→client push primitive with a default `RemoteEvent` signal transport, and a schema-driven binary codec). It now has runtime execution coverage: `apps/roblox-runtime-test` compiles the native runtime to Luau with `rbxtsc` and executes it under Lune (`lune/run.luau` via a minimal `TS` shim that loads the real roblox-ts `Promise` and resolves sibling imports), exercising the schema DSL, the `plain-data-v1` serialization boundary, the fixed-window rate limiter, server dispatch, the default `RemoteEvent` transport (round trip + request timeout), the server→client signal publisher/subscriber, and the binary codec round trips. This harness caught and fixed a real dispatch bug — a synchronously-throwing handler rejected the dispatch promise (leaving the transport's response handler unfired and the client waiting forever) instead of resolving an error payload; dispatch now wraps the handler call in `pcall`. This remains package-layout, rbxtsc compile, and Lune execution validation, not production Studio validation.

## Added beyond Phase 1 action transport

Two primitives extend the surface past the original action-only transport. They live in both the Node reference runtime (`packages/aruna/src`, vitest) and the roblox-ts native runtime (`packages/aruna/roblox`, Lune execution).

| Primitive            | Status | Notes                                                                                                                                                                                                                                                                                                                          |
| -------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `defineSignal` (server→client push) | Discovered | The push counterpart to `defineAction`: declare `{ id, payload? }`, publish with `to`/`toMany`/`toAll`, subscribe statically (app `handlers` map) or dynamically (`.on()` → `{ disconnect }`). Payload is validated against `plain-data-v1` + schema on publish (throws) and dropped on schema mismatch on delivery. Default native transport uses a dedicated `ArunaSignalRemoteEvent`. **Compiler-discovered**: the Rust compiler collects `defineSignal` exports into `manifest.signals` (`SignalRecord`), `aruna inspect signals` lists them, and they appear in the contract snapshot. Follow-up: extend `contract diff` to signal changes. |
| Schema-driven binary codec | Done | `encodeBinary`/`decodeBinary` pack a schema-conforming value into a byte buffer (Node `Uint8Array`, native Luau `buffer`) with a byte-identical wire format across both runtimes — no field names or type tags on the wire. **Numeric width hints** (`schema.u8()`/`u16()`/`u32()`/`i8()`/`i16()`/`i32()`/`f32()`, with `schema.number()` = `f64`) pack each number to its declared byte width and constrain integer validation to whole numbers in range. Widths flow through the Rust compiler into schema metadata (`numericFormat`) and the contract summary. To expose layout to the codec, the native schema now carries structural metadata (`item`/`fields`/`inner`/`value`/`values`/`members`) alongside `validate`. |

## Aligned with Notion spec

| Area                             | Status | Notes                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rust-owned compiler core         | Keep   | Compiler discovery, graphing, diagnostics, and manifest generation are Rust-owned.                                                                                                                                                                                                                                                                  |
| No TypeScript analyzer fallback  | Keep   | Native compiler loading is the only path.                                                                                                                                                                                                                                                                                                           |
| Config shape                     | Keep   | `defineConfig()` and the nested `compiler`, `actions`, `conventions`, `domains`, and `strict` config shape are implemented.                                                                                                                                                                                                                         |
| Layout conventions               | Keep   | Every file-name convention also classifies its folder form (`**/actions.ts` covers `**/actions/**`), so a concern splits into a folder with no config change. Matches rank directory glob → derived concern folder → file name.                                                                                                                     |
| Domain-to-domain boundary        | Keep   | A domain (`<root>/domains/*`, extended by `domains.roots`) keeps its `client/` and `server/` subtrees private; other domains import its root modules, or only its `index.ts` when it declares one. Violations report `aruna::304`, severity via `strict.domainBoundary` (warning by default). User-owned taxonomy stays user-owned: the rule is off with one field. |
| First-run DX flow                | Keep   | The intended flow is documented as `doctor --fix`, `check`, `build`, `inspect actions`, and `inspect contract --json`.                                                                                                                                                                                                                              |
| Action discovery                 | Keep   | Server action discovery and manifest emission exist.                                                                                                                                                                                                                                                                                                |
| Generated stubs                  | Keep   | Client/server action stubs are generated and snapshot-tested.                                                                                                                                                                                                                                                                                       |
| Inspect actions                  | Keep   | `aruna inspect actions` inventories client-callable actions, schema summaries, serialization policy metadata, rate limits, and basic authority notes.                                                                                                                                                                                               |
| Contract snapshot foundation     | Keep   | `aruna inspect contract` emits a deterministic JSON snapshot of the public action contract surface, including ids, source paths, generated export names, schema metadata and summaries, serialization policy, rate limits, authority notes, and warnings.                                                                                           |
| Contract diff command            | Keep   | `aruna contract diff` compares action contract snapshots or a baseline snapshot against the current project and reports breaking, non-breaking, and info-level changes.                                                                                                                                                                             |
| Authority visibility             | Keep   | The inspect command exposes server-owned actions and generated client-callable stubs without adding a full policy/capability system yet.                                                                                                                                                                                                            |
| Schema runtime validation        | Keep   | Action input/output validation runs at dispatch time.                                                                                                                                                                                                                                                                                               |
| Serialization boundary policy    | Keep   | Runtime now enforces the default `plain-data-v1` action boundary and rejects non-wire-safe input/output values.                                                                                                                                                                                                                                     |
| Basic action rate limit          | Keep   | Manifest-visible fixed-window rate limits are parsed and enforced per action and player/key.                                                                                                                                                                                                                                                        |
| Virtual generated imports        | Keep   | `$aruna/actions/client` and `$aruna/actions/server` are supported.                                                                                                                                                                                                                                                                                  |
| Package consumption validation   | Keep   | `apps/package-consumption-harness` validates package-style consumption through package resolution, package exports, `doctor --fix --emit-runtime`/`check`/`build --emit-runtime`/`inspect`/`contract diff`, the vendored-runtime tsconfig aliases, TypeScript, and a Luau `rbxtsc` compile. The packed `pnpm verify:package-consumption` tarball smoke resolves the local Aruna tarballs without registry access, vendors the native runtime, and compiles to Luau end-to-end. This is package-layout and rbxtsc compile validation, not production Studio validation. |
| `rbxts` harness                  | Keep   | The harness validates generated output, typecheck, and `rbxtsc`.                                                                                                                                                                                                                                                                                    |
| Recommended layout harness shape | Keep   | `apps/rbxts-harness` mirrors the recommended app/domain/shared layout for starter/reference use and now runs the turnkey `aruna build` (`--no-emit-runtime`, dist-mount) so the build itself drives `rbxtsc` to Luau against a single `out` Rojo mount. The earlier temporary partition layout shim (`out/client`/`out/server`/`out/shared`) was removed in favor of the turnkey build.                                     |

## Ahead-of-scope but retained

| Area                                        | Status | Notes                                                                                                                                                                                                                                                                                                                                             |
| ------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default Roblox `RemoteEvent` binding helper | Retain | Useful for current harness/tests, but do not expand.                                                                                                                                                                                                                                                                                              |
| Structural `RemoteFunction` transport       | Removed | Deleted (2026-07): the RemoteEvent request/response transport is a superset (timeouts, multiplexing, malformed-envelope drops) and the only supported transport. The `actions.transport` config field was removed with it.                                                                                                                        |
| Structural `RemoteEvent` transport          | Retain | The one action transport, shared by both runtimes over the flat `ReplicatedStorage/ArunaActionRemoteEvent`.                                                                                                                                                                                                                                       |
| Harness `default.project.json`              | Retain | Manual harness metadata only, with a conventional Roblox service tree and `rbxts_include` package mounting rather than generated Rojo integration. It no longer exposes Aruna-specific `App`/`Domains` nodes or a broad `out/` mount, but it still mounts the workspace `aruna` package inside `rbxts_include` as harness-only glue for `rbxtsc`. |
| Shared-safe app wiring                      | Keep   | The harness now wires client/server behavior from `src/client.tsx` and `src/server.ts` directly, while `src/app/bootstrap.ts` and `src/app/providers.ts` stay shared-safe helpers instead of hidden runtime entry files.                                                                                                                          |
| `aruna doctor --fix` path alias management  | Retain | Keep the minimal alias setup; do not broaden into more config automation yet.                                                                                                                                                                                                                                                                     |
| Basic action rate limit                     | Retain | The fixed-window runtime limiter exists, but it is not a full anti-abuse or policy system.                                                                                                                                                                                                                                                        |
