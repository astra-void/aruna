# Create App Plan

This note is the next-step planning target after package-consumption validation.
It does not describe an implemented `create-app` command.

## Intended starter output

- `src/client.tsx`
- `src/server.ts`
- `src/app/bootstrap.ts`
- `src/app/providers.ts`
- `src/domains/*`
- `src/shared/*`
- `src/.aruna/*` generated by Aruna

## Installation strategy

- Prefer a package-based install path for Aruna and its compiler.
- Keep the current workspace validation harness as a reference until a public install flow is proven.
- Do not rely on `../../packages/aruna/dist` in starter source or Rojo metadata.

## Generated `.aruna` policy

- `doctor --fix` should install generated action aliases.
- `build` should generate action stubs and the manifest.
- Contract snapshot and diff metadata stay separate from the generated action stubs.

## Rojo strategy

- Start with a conventional `default.project.json`.
- Prefer package-style resolution for Aruna runtime imports.
- Do not generate Roblox Instances yet.

## Output layout shim

- Keep the current rbxts layout shim harness-only for now.
- Do not promote the temporary split output into product code yet.

## Deferred

- `create-app`
- generated Rojo scaffolding
- generated Roblox Instances
- Studio runner flow
- `defineResource`
- policies and capabilities
- sessions
- resource invalidation
